# Connection Flood Tester

TCP 연결을 대량으로 맺고 닫지 않아 서버의 **동시 연결 자원을 소진**시키는 L7 DoS 테스트 도구.
Slowloris 계열로, 요청을 완성하지 않고 헤더를 조금씩 흘려보내 연결을 오래 붙잡는다.
사전 학습·방어 검증 목적으로, 본인이 통제하는 격리 환경에서만 사용한다.

> ⚠️ **본인 소유이거나 명시적으로 허가받은 시스템에만 사용해야 합니다.**
> 타인의 서버를 무단으로 공격하는 행위는 정보통신망법 등 관련 법률 위반이며,
> 그로 인한 책임은 사용자 본인에게 있습니다. 이 프로젝트는 보안 학습 및 인가된 테스트 목적으로만 제공됩니다.

---

## 동작 원리

일반적인 요청 폭탄(GET flooding)과 달리, 이 도구는 **연결을 끊지 않고 붙잡는 데** 초점을 둔다.

1. TCP 연결을 맺고 `GET / HTTP/1.1` 요청을 **일부러 완성하지 않는다** (마지막 빈 줄을 안 보냄).
2. 서버는 "요청이 아직 안 끝났다"고 판단해 연결을 계속 열어둔다.
3. 주기적으로 의미 없는 헤더 한 줄씩만 흘려보내 타임아웃을 방지한다(Slowloris식).
4. 이렇게 연결 슬롯을 점유하면, 서버의 동시 연결 한도가 차서 정상 사용자의 접속이 막힌다.

적은 대역폭으로 서버 자원을 묶을 수 있어, 특히 **연결당 프로세스/스레드를 쓰는 서버(예: Apache prefork)**에 효과적이다.

## 왜 멀티프로세싱인가

네트워크 요청은 I/O 바운드지만, 이 도구는 **수천 개의 연결 상태를 동시에 유지·관리**해야 하므로
여러 프로세스로 나눠 각 프로세스가 자기 연결 묶음을 담당하게 했다.
프로세스 간에는 `multiprocessing.Value`로 살아있는 연결 총수를 공유해 실시간으로 표시한다.

## 요구 사항

- Python 3.x
- **외부 라이브러리 없음** (표준 라이브러리 `socket`, `multiprocessing` 등만 사용)

## 사용법

```bash
python Connection_Flood_Dos.py
```

실행하면 대상 URL/IP와 포트를 입력받는다.

```
URL/IP: 192.168.0.10
포트(기본 80): 80
```

- 대상 주소는 IP(`192.168.0.10`) 또는 호스트명(`test.local`) 모두 가능하며, 호스트명은 자동으로 IP로 변환된다.
- 중단하려면 `Ctrl+C`.
- 실행 중 **유지 중인 연결 수**가 1초마다 출력된다.

## 결과 읽는 법

- **"유지 중인 연결" 수가 오르다 멈추면** → 서버가 더 이상 연결을 받지 않는 지점(한도 도달)일 수 있다.
- 이때 브라우저나 `curl`로 대상에 접속해 **응답이 느려지거나 막히는지** 확인하면 실제 효과를 검증할 수 있다.
- 서버 쪽에서 `netstat -ant | grep ESTABLISHED | wc -l`로 실제 물린 연결 수를 대조할 수 있다.

## 방어 관점 (같이 보면 좋음)

이 공격이 통하는지, 그리고 방어가 어떻게 막는지를 함께 실험하면 학습 가치가 크다.

- **Apache**: `mod_reqtimeout`으로 느린 요청을 끊고, `MaxRequestWorkers`로 한도를 관리
- **nginx**: 이벤트 기반이라 구조적으로 강하며, `limit_conn`으로 IP당 연결 수 제한
- 방어를 껐을 때 vs 켰을 때 "유지 중인 연결" 곡선을 비교하면 방어 효과가 데이터로 드러난다

## 한계

- 단일 호스트에서 실행하므로, 공격자 쪽 **임시 포트(ephemeral port) 고갈**(대략 수만 개)이 한계다.
  그 이상은 한 대로는 불가능하다.
- 연결 소진에 강한 서버(nginx 등)나 적절한 방어가 설정된 서버에는 통하지 않는다
  (그것이 정상이며, 올바른 방어의 예다).
